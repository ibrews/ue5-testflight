# UE5 TestFlight Pipeline Skill

You have access to a fully automated UE5 → TestFlight pipeline for iOS and visionOS. The pipeline runs on a macOS build machine via LaunchAgents and is triggered by `launchctl start` commands.

## Configuration

Before using, check that `ue5kit.conf` is filled in and `setup.sh` has been run. The config file sets `$ORG_LABEL` (LaunchAgent prefix), `$IOS_PROJECT_PATH`, `$VISIONOS_PROJECT_PATH`, and all ASC credentials.

## Triggering Builds

```bash
# Full pipeline: build → sign → upload → distribute
# iOS (cook + stage + ship + TestFlight attach)
launchctl start $ORG_LABEL.iosbuild

# visionOS (cook + stage + sign + icon inject + upload + TestFlight attach)
launchctl start $ORG_LABEL.visionosbuild

# macOS (cook + stage + sign + zip + upload + TestFlight attach)
launchctl start $ORG_LABEL.macosbuild
```

Replace `$ORG_LABEL` with the value from `ue5kit.conf` (e.g. `com.yourcompany`).

## Monitoring

```bash
# iOS
tail -f /tmp/ue5kit-ios-build.log      # build phase
tail -f /tmp/ue5kit-ship-ios.log       # sign/upload/distribute phase

# visionOS
tail -f /tmp/ue5kit-visionos-build.log
tail -f /tmp/ue5kit-ship-visionos.log

# macOS
tail -f /tmp/ue5kit-macos-build.log
tail -f /tmp/ue5kit-ship-macos.log
```

Build phase takes 30–60 min. Ship phase takes 5–10 min (iOS/macOS) or 30–60 min (visionOS ASC processing).

## Ship Only (Skip Build)

If a build is already staged and you only need to re-ship:

```bash
launchctl start $ORG_LABEL.shipios
launchctl start $ORG_LABEL.shipvisionos
launchctl start $ORG_LABEL.shipmacos
```

The ship scripts auto-increment `CFBundleVersion` on every run to avoid duplicate build number errors.

## Manual External Group Attach

visionOS builds take >30 min to process in ASC. If the poll times out:

```bash
python3 scripts/attach_to_group.py visionos
python3 scripts/attach_to_group.py ios
python3 scripts/attach_to_group.py macos
```

## Key Gotchas

- **Never run `codesign` directly over SSH** — it silently fails even with the correct keychain. Always trigger via `launchctl start` (GUI session / LaunchAgent).
- **UE5 ignores `BundleIdentifier`** in DefaultEngine.ini for iOS builds. The ship scripts patch `CFBundleIdentifier` in the staged `.app/Info.plist` post-build.
- **iOS 30fps default** — must set `FrameRateLock=PUFRL_None` in `DefaultEngine.ini` AND the CVars in `DefaultDeviceProfiles.ini`. Neither alone is sufficient.
- **visionOS crashes after splash** without `Config/VisionOS/VisionOSEngine.ini` and `VisionOSDeviceProfiles.ini` in the project. Copy from `ue5-config/VisionOS/`.
- **Half-transparent rendering in mixed immersion** — `r.MobileHDR=False`, `r.ForwardShading=True`, and `r.Mobile.ShadingPath=0` must all be present in `DefaultEngine.ini`. Missing any one of them causes the HDR/deferred pipeline to mishandle the alpha channel, making geometry appear semi-transparent.
- **visionOS transparent scene (passthrough only, no content)** — two possible causes: (1) `xr.OpenXRInvertAlpha=True` missing from `[/Script/OpenXRHMD.OpenXRHMDSettings]` in DefaultEngine.ini — without it UE5 renders transparent; (2) `GameDefaultMap` points to an engine map that doesn't get cooked — use a project-owned map in `Content/`.
- **visionOS baked lighting missing** — `r.AllowStaticLighting=False` in DefaultEngine.ini silently disables `_BuiltData.uasset`. Set to `True`.
- **OpenXRVisionOS plugin** lives at `Engine/Platforms/VisionOS/Plugins/Runtime/OpenXRVisionOS/` — not in `Engine/Plugins/`. Add `{"Name": "OpenXRVisionOS", "Enabled": true}` to your `.uproject`.
- **Touch controls on visionOS** — `DefaultTouchInterface=None` in `Config/DefaultInput.ini` under `[/Script/Engine.InputSettings]`. UE5 defaults to virtual joysticks which show on visionOS.
- **One eye black on visionOS (UE5 5.7 bug)** — add `r.AllowOcclusionQueries=False` to `[/Script/Engine.RendererSettings]` in DefaultEngine.ini.
- **Testing mixed immersion** — hide the sky sphere mesh in your level. Sky opaque = can't verify passthrough. With sky hidden: passthrough = mixed immersion working; black = alpha pipeline issue.
- **visionOS icon** is auto-generated by `gen_visionos_icon.py`. Apple requires a `.solidimagestack` asset — `CFBundlePrimaryIcon` must be a string (`"AppIcon"`), not a dict (ITMS-90039).
- **plist patching must use a standalone script** — `python3 - << HEREDOC` in LaunchAgent context silently fails to write plist files (`plistlib.dump` doesn't persist). Always use `/opt/homebrew/bin/python3 plist_patch.py`.
- **iOS builds also run on Vision Pro** via the iOS compatibility layer. You don't need a visionOS build to test on the headset.
- **AutomationTool mutex** — UE5 only allows one RunUAT at a time. Don't trigger iOS, visionOS, and macOS builds simultaneously.
- **macOS signing cert** is `3rd Party Mac Developer Application` (not iPhone Distribution). The `MACOS_CERT_SHA1` must point to this cert in the CI keychain.
- **macOS Info.plist is at `Contents/Info.plist`** inside the .app bundle — unlike iOS where it's directly inside the .app.
- **macOS upload uses `--type macos`** and a `.zip` of the .app (not an IPA).
